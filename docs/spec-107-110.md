# Specification: GitHub Issues #107 and #110

**Status:** Approved
**Date:** 2026-10-20

This document specifies two independent profile experience improvements. Each section can be implemented and reviewed separately.

## Issue #107: Owner shortcut on published profiles

**Issue:** [#107 — Add an owner-only dashboard shortcut on published profiles](https://github.com/wehyn/tapit/issues/107)

### Goal

Let a signed-in profile owner quickly open the dashboard to edit the published profile they are viewing.

### User behavior

1. A visitor opens a published profile.
2. Tapit confirms the viewer's identity and profile ownership using server-verified account data.
3. If the viewer owns that profile, show a floating **Edit profile** shortcut that opens `/app/profile`.
4. Hide the shortcut for signed-out viewers, non-owners, and viewers whose ownership check is pending or unsuccessful.
5. Keep the existing authenticated editor and backend authorization checks as the authority for editing. The shortcut is navigation only; it does not grant access.

### Requirements

- Ownership must be confirmed from the authenticated server identity. Do not trust a client-supplied owner ID or role.
- Compare the viewed profile ID with the authenticated viewer's owned profile from an existing server-authorized query, such as `api.profiles.mine`.
- Keep owner identity out of the public profile projection. The ownership result must not reveal owner IDs or profile details to other viewers.
- Only the actual owner sees the shortcut; an administrator who does not own the profile does not qualify under this issue.
- Apply the same owner-only behavior in local demo mode using its existing demo session and profile data.
- The shortcut must remain usable at mobile and desktop sizes and must not obscure profile content or existing controls.

### Acceptance criteria

- A signed-in owner sees the shortcut on their published profile and it opens the profile dashboard/editor.
- A signed-out viewer does not see the shortcut.
- A signed-in viewer who does not own the profile does not see the shortcut.
- An unresolved or failed ownership check never shows the shortcut.
- The public profile response does not expose owner identity, and editing remains protected by existing server-side authorization.

### Out of scope

- Changing the public profile contents or general account navigation.
- Giving visitors or administrators access to the owner's editor through this shortcut.
- Changing profile publication, ownership, or account permissions.

## Issue #110: Full-image view on published profiles

**Issue:** [#110 — Add a “View image” action for slideshow images](https://github.com/wehyn/tapit/issues/110)

### Goal

Let a visitor see the complete uploaded image in a published profile's slideshow when the normal slideshow crops it to fit its frame. Long-pressing an image may open the full image on some devices, but that behavior is inconsistent; the profile needs an explicit **View image** action.

### User behavior

1. A visitor navigates to or selects a slideshow image on a published profile.
2. The currently displayed image has a clearly labeled **View image** action.
3. Activating the action opens that image at its full aspect ratio in a dismissible dialog.
4. Closing the dialog returns the visitor to the same selected slideshow image.

### Requirements

- Put the action in the published slideshow and associate it with the currently displayed image, including when the slideshow contains only one image.
- Use the public image source already supplied to the slideshow. Do not depend on long-press or browser context-menu behavior.
- Show the whole image, preserving its aspect ratio and scaling it to fit the available viewport without cropping it.
- Preserve the image's alternative text in the full-image view.
- Provide a visible close control, support Escape to dismiss, and restore focus to the action that opened the view.
- Make the view usable on desktop and mobile, including when the image is taller or wider than the viewport.
- Pause autoplay while the full-image view is open. Closing it returns to the same selected slideshow image.
- Do not change the normal slideshow's existing crop, navigation, or autoplay behavior outside the full-image view.

### Acceptance criteria

- Every image in a published slideshow, including a single-image slideshow, can be opened with a labeled **View image** action.
- The action opens the currently displayed image in full, without cropping it.
- The full-image view is easy to dismiss by keyboard and by its visible close control.
- Closing the view returns to the same selected image and does not advance autoplay while it is open.
- The view remains usable on desktop and mobile viewports.

### Out of scope

- Editing, cropping, zooming, downloading, or replacing an image from the full-image view.
- Changing the crop or navigation behavior of the normal published slideshow.
- Adding a new image library or dependency.

## Verification notes

- For #107, verify owner, signed-out, non-owner, and unresolved-ownership states in both live and local demo modes. Confirm the owner can reach the editor, a non-owner does not see the shortcut, and existing server authorization still prevents editing another account's profile.
- For #110, verify the action for single- and multiple-image slideshows, correct full image, no cropping, close control, Escape handling, focus restoration, paused autoplay, and desktop/mobile sizing.
- Keep the two changes independently reviewable. No shared backend or data-model change is required by these specifications.
